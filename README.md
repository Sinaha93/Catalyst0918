# 촉매 마감 관리

## 이월·정산 자동 연결과 고급 설정

촉매사 마감파일을 해당 월로 등록하면 전월 이월·당월 정산 수량을 자동으로 읽습니다. 전월 확정 마감이 있으면 확정 이월을 우선합니다. 희성촉매는 납품처별 정산 열, 유미코아는 현재 BOM 및 검증 가능한 비고 배부를 사용하며 ERP 입고를 중복 등록하지 않습니다. 불명확한 납품처만 확인합니다. 알려진 파일은 전용 등록 화면을 사용하고, 미등록 양식의 열 연결은 왼쪽 **고급기능 → 열 연결**에서 설정합니다.

왼쪽 **고급기능 → 단가 적용일 상세 설정**은 실제 월중 단가가 바뀐 경우에 사용합니다. 일반 BOM·구매단가 연결에서는 사용할 마감 월을 선택하면 그달 1일을 적용 기준일로 제안하며, 미리보기 후 반영 버튼을 눌러야 저장됩니다. 화면 변경만으로 기존 단가의 적용일을 바꾸지는 않습니다. 전월 확정 이월 금액은 유지됩니다.

## 실행

이 PC에서는 **`촉매마감관리_실행.lnk` 바로가기**를 더블클릭합니다. 설치된 Python으로 최신 소스를 실행하고 기본 브라우저에서 `http://127.0.0.1:8765`가 열립니다. 새 EXE는 Smart App Control의 게시자 검증으로 차단되어 현재 권장 실행 경로가 아닙니다. 보안 설정은 변경하지 않았습니다.
콘솔 창 없이 백그라운드에서 실행되고 브라우저만 열립니다. 화면 왼쪽 아래 **프로그램 종료**를 누르면 서버와 폴더 감시가 종료됩니다. 브라우저만 닫으면 계속 실행되며, 실행 파일을 다시 열면 기존 서버 화면으로 연결됩니다. 실행 기록은 `logs/application.log`에 보관됩니다.
자료 등록과 계산은 인터넷 연결 없이 동작합니다. 보고서 출력에는 Windows용 Excel이 필요합니다. PowerPoint는 필요하지 않습니다.
프로젝트 폴더에 데이터가 저장되므로 쓰기 가능한 폴더에서 사용하세요. 바로가기는 `.venv`, 소스 코드, `frontend/dist`가 필요하며 단독 배포용 파일은 아닙니다.

## 사용 순서

고급기능에는 **품번별 예외 규칙 / 납품처 배부 수정 / 자료 반영 이력**이 있습니다. 예외 규칙은 선택한 월의 촉매사 이월·정산을 특정 납품처에 전량 연결하며 사용 해제할 수 있습니다. 전월 확정 이월·직접 입력·명시적 배부 수정이 우선합니다. 배부 수정은 자동/기존 배부를 다시 수정할 수 있지만 원본 총수량과 사유 검증을 통과해야 합니다. 확정 마감과 ERP 입고는 변경하지 않습니다. 이력은 기본 접힘 상태이며, 유형·검색어·작업일로 검색하고 20건씩 이전/다음 페이지로 조회하며 변경 전후 기록이 있는 항목을 비교합니다. 고급기능에는 백업·복구 메뉴를 추가하지 않았습니다.

자료 등록의 **등록 자료 전체 초기화**는 모든 월의 파일 등록과 해당 자료의 반영 내역을 비웁니다. 영향 범위 확인 후 ‘초기화’를 입력해야 실행되며 자동 백업합니다. 원본/input/archive 파일, 확정 마감, 생성 보고서, 독립적인 직접 입력, 직접 관리한 품번 연결·예상 단가, 열 연결 양식은 유지합니다. 파일에서 파생된 수정 내역은 초기화 대상입니다. 같은 파일은 자동으로 다시 나타나지 않지만 직접 업로드하면 재등록할 수 있습니다. 다음 달로 넘어가기 위해 초기화할 필요는 없습니다.

자료 등록의 **필수 자료 안내**에서 BOM·구매단가·ERP 입고·두 촉매사 마감·당월 정산·이월·월계획·보고 Excel 양식을 확인합니다. 목록에도 필수/기존 마스터/PPT 비필수 등을 표시합니다. 월별 반영은 선택 월의 활성 내역, 이월은 전월 확정본·직접 입력을 구분합니다. 촉매사 비교 자료는 등록만으로 월·수량 검증 완료로 표시하지 않습니다. 역할을 아직 판별하지 못한 파일은 역할 확인 필요로 표시합니다.

1. **자료 등록**: 파일을 업로드하거나 `input` 폴더에 복사합니다. 기존 폴더 전체 읽기는 제거했습니다.
2. **등록 확인**: 유미코아·희성촉매는 ‘마감자료 등록’, ERP는 ‘입고 등록’에서 대상 월만 지정합니다. BOM·구매단가는 전용 연결 화면을 사용합니다. 지원하지 않는 새로운 양식만 ‘등록 설정’에서 열 연결이 필요합니다.
3. **마스터 관리**: 품번과 적용일별 단가, 기초 이월, 입고, 정산, 계획 등을 등록합니다. 표 붙여넣기와 기존 값 수정도 지원합니다. 수정 사유는 필수입니다. 예상 정산 단가는 실제 단가와 별도로 등록하며, Excel 미정산 시트 O:V 참고표에 출력합니다. 예상값은 실제 정산·다음 달 이월에 합산하지 않습니다.
4. **확인 필요**: 단가 누락·미등록 품번·음수 미결 등 오류를 보완합니다. 수량과 금액의 원본 근거를 열어볼 수 있습니다.
5. **마감 현황**: 월과 결과를 확인하고 확정합니다. 같은 월을 정정하면 v2, v3 형태로 보존합니다.
6. **보고서·이력**: 확정 버전의 엑셀만 생성하고 다운로드합니다. PPT는 엑셀의 그래프·표를 직접 붙여넣어 작성합니다.

단가와 금액은 **원 단위**로 입력합니다. 보고서의 천원 표시는 표시 단위이며 저장 금액은 원입니다.
입고·정산이 없는 달도 0건 자료가 아닌 **수량 0행**으로 명시해야 합니다.
단가가 달라지는 날부터 새 적용일로 등록합니다. 같은 품번·거래처·적용일의 상충 단가는 차단됩니다.

## 안전 규칙

### 월계획 자동 등록

`계획` 시트의 `일자 / 품번 / 거래처 / 수량 / 단가(원) / 금액(원) / 비고` 양식은 열 연결 없이 읽습니다. **새 월계획은 업로드하면 검증 후 자동 반영**됩니다. 파일명이 달라도 인식하며 대상 월은 파일 내부 일자를 사용합니다. 빈 수량은 0으로 간주하지 않고, 명시된 0은 보존합니다. 한 달·중복 품번/납품처·수량×단가=금액을 검증합니다.

같은 월 수정본은 **계획 확인**에서 합계를 보고 교체를 확인합니다. 직접 입력이나 다른 방식의 계획과 충돌하면 자동 합산하지 않습니다. 실제 단가·입고·정산·다른 월 계획은 변경하지 않습니다. 이미 등록한 동일 파일은 중복 반영하지 않습니다.

### 촉매사 마감자료 간편 등록

한국유미코아·희성촉매 양식은 열 연결을 하지 않습니다. **자료 등록 → 마감자료 등록 → 대상 월 선택 → 자료 확인 → 해당 월 마감자료로 등록** 순서입니다. 파일명이 달라도 표의 제목으로 판별하며 기존에 올린 파일도 재업로드 없이 사용합니다. 등록 후 같은 버튼은 **수량 비교**로 바뀝니다.

한국유미코아는 `Total 납품`, 희성촉매는 `출하`를 ERP 월 입고와 품번별 비교합니다. 전월 이월·정산·잔량도 별도로 읽고 합계와 수량 관계를 검증합니다. 차이를 자동 보정하지 않으며 ERP 등록 전에도 비교 자료를 먼저 저장할 수 있습니다. 동일 월·촉매사의 수정본은 이전 비교 자료를 대체합니다.

**ERP 입고에 다시 합산하지 않습니다.** 월이 등록된 촉매사 자료의 이월·정산은 마감 계산에 자동 연결합니다. 희성의 납품처별 수량, 단일 BOM 납품처, 이월·잔량 0인 전량 정산 등 수량이 명확한 경우만 사용합니다. 전월 확정 이월은 금액까지 그대로 유지하며, 원본 합계와 다르면 확정을 차단합니다. 직접 입력과 중복 합산하지 않습니다.

납품처가 불분명한 경우 **자료 등록 → 이월·정산 연결 확인**에서 해당 품목을 펼쳐 납품처별 수량과 확인 사유만 입력합니다. 원본 합계와 같아야 저장됩니다. 기존 자료와 충돌하는 항목은 먼저 기존 입력을 확인해야 합니다. 확인값은 해당 원본·월에만 적용하며 원본 삭제·교체 시 이전 자료의 계산 연결도 제외됩니다. 과거 확정 마감은 변경하지 않습니다.

ERP 수량 비교 범위는 해당 촉매사 파일의 품번입니다. 계산 시에는 ERP에만 있는 품번의 이월·정산 누락도 확인 대상으로 남깁니다. 두 촉매사에 같은 품번이 있으면 자동 배부하지 않습니다. 필수 자료 안내는 ‘파일 없음’, ‘마감 월 등록 필요’, ‘납품처 확인’, ‘계산 연결됨’을 구분합니다.

### ERP 월 입고 전용 등록

`기간별구매거래처입고현황`의 거래처별 가로 수량 양식은 **ERP 월 입고현황 → 입고 등록**을 사용합니다. 이미 등록한 동일 양식에도 자동 표시되며 재업로드할 필요가 없습니다. 대상 월을 선택하고 미리보기 합계를 확인한 다음 ERP 조회 월이 맞다는 확인란을 체크해 반영합니다. 파일명 작성일이나 폴더명으로 월을 자동 추정하지 않습니다.

품번별 전체 합계와 거래처 수량 합계, TOTAL의 전체·거래처별 합계를 모두 대사합니다. 합의한 CONVERTER 두 품번은 제외량으로 따로 표시하고 촉매 수량만 반영합니다. `CATALYST`, `CATALYST-FR/RR/GPF`, `CATALYST GPF`를 지원합니다. 미등록 거래처·다른 품목·음수·양식 변경은 확인 대상으로 차단합니다. ERP 품번의 R600 접두사를 제거하고 거래처를 표준 명칭으로 연결합니다.

월 집계 파일에는 개별 입고일이 없으므로 선택 월의 말일을 집계 기준일로 기록합니다. 실제 입고일을 복원한 것이 아닙니다. 금액은 별도 마스터 단가로 계산하며 단가 누락은 마감 확인 사항에 남습니다. 같은 월의 전용 ERP 자료는 수정본으로 교체하되 다른 월은 보존합니다. 기존 일반 입력·직접 입력 입고가 같은 월에 있으면 중복을 막기 위해 자동 합산하지 않습니다. 이 양식은 일반 열 연결로 반영할 수 없습니다.

자료 등록 목록의 파일명 아래 **저장 위치 확인**을 누르면 실제 보관 사본 경로와 **경로 복사** 버튼을 볼 수 있습니다. 새 등록부터 읽어온 위치도 기록합니다. 과거 자료의 미기록 원본 위치는 추측하지 않습니다. 브라우저 업로드는 사용자가 선택한 원본 PC 폴더를 알 수 없으므로 서버의 input 위치로 구분 표시합니다.

- 동일 파일 내용은 SHA-256으로 중복 반영을 차단합니다.
- 교체는 같은 자료 묶음과 같은 입력 월 집합에 한정됩니다. 월별 파일은 한 달씩 등록하는 것을 권장합니다.
- 양식 자동 반영은 시트·제목 행 일치와 **날짜 열 연결**이 필요합니다. 공통 날짜만 지정한 양식은 다음 파일을 자동 반영하지 않습니다.
- 수동 수정한 자료 묶음의 후속 파일 교체는 자동 적용하지 않습니다.
- 거래처를 자동 추측하지 않습니다. 출하를 입고·정산으로 임의 간주하지 않습니다.
- 누락 단가를 0원으로 처리하지 않습니다. 기초 이월 금액은 전월 확정 재고가액 또는 명시한 값을 사용합니다.
- 수량 조정만으로 재고가액을 계산하지 않습니다. 금액을 포함한 입고/정산 정정으로 처리해야 합니다.
- 확정에는 입력 내역·단가·계산 결과·보고서 양식 해시·과거 확정 실적을 보존합니다.
- 원본 파일은 수정하지 않습니다. 산출물은 `outputs`에 생성합니다.

## 저장과 복구

| 폴더 | 내용 |
|---|---|
| data | SQLite 마스터와 처리 이력 |
| archive | 내용 해시별 원본·확정 시점 보고서 양식 |
| input | 자동 감시 폴더 (실행 중에만 감시) |
| outputs | 생성 보고서 |
| backups | 시작·마감·수동 요청 시 SQLite 백업 |

화면의 백업·복원은 **데이터베이스 시점 복구**입니다. 원본 파일은 archive에서 계속 보존합니다.
다른 PC로 옮기거나 전체 장애에 대비하려면 프로그램을 종료하고 위 폴더들과 실행 파일을 **함께** 복사해야 합니다. backups만 복사하면 원본과 보고서 양식이 빠집니다.

## 현재 범위와 운영 전 확인사항

실제 8월 자료 초기 이관·수량 대사와 계획 등록을 수행했고, 운영 DB에 2026-08 확정 v1이 있습니다. `august_bootstrap.py`는 이 기간 전용 초기 이관 코드이며 월별 범용 자동 마감 완료를 의미하지 않습니다. 원본 저장 결과를 사용한 초기 이월·정산에는 출처와 이관 표식을 남깁니다. 기존 보고서의 모든 금액이 일치한다고 보장하지 않습니다.

새 BOM 마스터와 구매단가등록은 등록·검증 완료, **적용 기준일 사용자 확인 대기**입니다. 아직 운영 계산의 단가를 교체하지 않았습니다. 주문전송은 마감 필수 자료가 아닙니다. 상세 기준은 BUSINESS_RULES.md를 따릅니다.

신규 월·변경 양식·출하 배부와 보고서 과거 누적 수치에 대한 지속적인 업무 검증은 필요합니다. 현재 기능은 개인 Windows PC용이며 인터넷·AI API 없이 핵심 처리를 합니다. 자연어 입력과 월계획 매크로 자동 실행은 제공하지 않습니다.

기존 거래처 10곳의 엑셀 14개 시트를 사용합니다. 월별 계획·실적 그래프와 미정산 납품처별 소계를 유지합니다. PPT 자동 생성은 제거했으며, 기존 PPT 원본·출력 파일은 삭제하지 않습니다.
거래처별 내장 계산서는 현재 한 페이지 이미지입니다. 품목이 매우 많거나 비고가 길 때는 출력 검토가 필요합니다. 신규 거래처는 양식 어댑터 추가가 필요합니다.
공장·차종·공급업체는 마스터 관리의 연결 정보에서 관리합니다. 전용 출하 배부, 상세 내장 계산서 자동 분할 및 모든 장표의 장문 자동 페이지 분할은 후속 구현 대상입니다.

## 개발

### BOM·구매단가 연결 및 자료 삭제

이 PC에서는 `촉매마감관리_실행.lnk`를 더블클릭해 설치된 `.venv/Scripts/pythonw.exe`로 실행할 수 있습니다. 검은 콘솔 창 없이 브라우저가 열립니다. 기존 프로그램이 실행 중이면 먼저 화면에서 프로그램을 종료한 뒤 새 바로가기를 실행하세요. 바로가기는 이 폴더의 소스·가상환경·프론트엔드 빌드가 필요하므로 단독으로 다른 PC에 복사하는 배포 파일은 아닙니다. 바로가기 재생성은 `python tools/create_python_shortcut.py`로 합니다. Windows 보안 설정은 변경하지 않습니다.

최신 프로그램의 자료 등록 화면에서 **BOM·구매단가 연결**을 사용합니다.
1. BOM 마스터와 구매단가등록 엑셀을 등록합니다. 시트와 열 제목으로 판별하므로 파일명 날짜가 달라도 됩니다.
2. 두 파일과 적용 기준일을 선택하고 변경 단가를 미리 확인합니다. 파일명 날짜나 ERP 입력일은 적용일로 자동 사용하지 않습니다. 현재 ERP 스냅샷을 사용자가 확인한 적용일 기준으로 반영합니다.
3. 변경 사유를 입력하고 반영합니다. BOM의 촉매 입력품번·마감처·촉매사를 사용하며, 구매거래처를 촉매사로 간주하지 않습니다. `R600/M/H` 접두사와 `_CKD` 접미사만 정규화합니다. 동일 품번의 구매처별 단가가 다르면 자동 선택하지 않습니다.

이 기능은 월계획 매크로를 실행하거나 월계획 수량을 재계산하지 않습니다. 월계획 등록은 기존 계획 파일로 계속 처리합니다. `28991-4C520`의 마감처는 현대 전주로 유지하고 실제 단가와 예상 정산 단가는 분리합니다. 과거 단가 기록·확정 마감은 보존합니다.

입력 자료 오른쪽 **삭제 → 등록만 삭제**는 목록과 미확정 계산에서만 제외합니다. 원본·`archive` 보관 사본·`input` 업로드 파일은 삭제하지 않습니다. 영향 파일·건수·기간과 사유를 확인한 후 실행하며, 연결된 마스터 쌍이나 초기 이관 자료는 함께 처리합니다. 직접 수정한 파생 내역도 원본 연결이 있으면 포함합니다. 독립적으로 직접 입력한 품번 연결은 유지합니다.

확정 마감·증빙·양식·감사 기록·중복 방지 해시·기존 백업은 유지됩니다. 자동 수집은 삭제한 등록을 되살리지 않지만 직접 업로드하면 같은 파일을 새로 등록할 수 있습니다. 이전 반영 내역을 재활성화하지 않고 새 반영으로 처리합니다. 다음 달에는 마감 월을 변경하고 ERP 입고·촉매사 마감·월계획을 새로 등록하세요. BOM·단가·양식은 변경 시에만 갱신하며 전월 확정 이월은 자동으로 이어집니다. 전체 초기화는 필요하지 않습니다.

**보고서·이력 → 생성한 보고서 → 삭제**는 선택한 Excel/JSON 출력 파일을 실제 삭제합니다. 확정 마감 이력은 삭제하지 않으므로 보고서를 다시 생성할 수 있습니다. 열려 있는 파일은 닫은 후 삭제해주세요. 기존 DB 전체 백업·복구 기능은 개별 자료 복원과 별개로 유지됩니다.

Python 3.12 환경에서 `pip install -r requirements.txt` 후 `python launcher.py`로 실행합니다.
프론트엔드는 `frontend`에서 `npm ci`와 `npm run build`로 빌드합니다.
`python -m pytest -q`는 격리된 저장소에서 테스트합니다.
`python tools/verify_office.py`는 임시 폴더에 가상 자료를 넣고 Office 출력 흐름을 확인합니다. 운영 DB에는 테스트 자료를 넣지 않습니다.
`tools/check_render.py`는 과거 PPT 기능의 검증용 도구이며 현재 엑셀 전용 운영에서는 사용하지 않습니다.
`powershell -ExecutionPolicy Bypass -File build.ps1`은 단일 실행 파일을 빌드합니다.

기존 `app.py`는 초기 분석 도구로 그대로 보존했습니다. 새 프로그램 진입점은 `launcher.py`입니다.
